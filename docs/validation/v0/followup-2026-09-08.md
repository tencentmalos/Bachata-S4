# V0 复核与缓存失效修复（2026-09-08）

**结论：已定位并修复这一轮 guest 执行失败的主因，Swan 上执行 harness 从 33 项中 13 FAIL 变为原有 33/33 PASS，加入缓存回归后 36/36 PASS。V0 仍为 `V0_IN_PROGRESS`。**

复核对象为用户提供的上一轮执行叙述及其落地源码。主仓起点 `9890727ad4a0e76d2c2120042d1b8a7f3316b2a5`，FEX `385a0cc4d81cd456c8d5c26b4f09cb5a7d8d5842`；本轮改动位于主仓工作区，未提交、未 push，FEX 子仓保持干净。范围为 Swan / Android 16 / ARM64 / **4 KiB**，不以 16 KiB 为当前门槛。

## 1. 问题来源

错误位于主仓 [FEX adapter 的 InvalidateCode](../../../src/core/guest_cpu/fex/fex_context.cpp)，不是本次证据所能支持的 bionic store/load 或 TSO 故障。

1. `RunFixture` 运行第一段 integer fixture，随后销毁 guest 线程。
2. 下一个 fixture 覆盖相同 guest VA，调用 `InvalidateCode`。
3. 旧实现只遍历 `threads_` 调用 `ClearCodeCache`。线程数为零时不做失效，但仍返回成功。
4. FEX context 的共享 CodeBuffer/L3 翻译缓存继续存活；新线程再次访问该 VA 时可执行旧 integer 翻译。

这样，第一段整数结果正确，但后续 branch、push/pop、store、SSE2 的预期效果消失，裸 HLT 也可能沿旧翻译进入 return gate。它们是同一个缓存生命周期错误的多种表现。

源码依据为本次固定 FEX 版本的 [公开失效接口](https://github.com/tencentmalos/FEX/blob/385a0cc4d81cd456c8d5c26b4f09cb5a7d8d5842/FEXCore/include/FEXCore/Core/Context.h#L142)、[共享及线程缓存实现](https://github.com/tencentmalos/FEX/blob/385a0cc4d81cd456c8d5c26b4f09cb5a7d8d5842/FEXCore/Source/Interface/Core/Core.cpp#L1067)、[Windows frontend 的调用顺序](https://github.com/tencentmalos/FEX/blob/385a0cc4d81cd456c8d5c26b4f09cb5a7d8d5842/Source/Windows/Common/InvalidationTracker.cpp#L329)。这些来自本地对应 SHA 的源码检查。

上一轮把“同一 fixture 重跑仍失败”当作排除旧缓存的依据不成立：反复命中同一旧翻译恰好会产生稳定错误。RSP 未变和三个读取入口都读零，也不足以证明目标 push/pop 或 store 指令实际被执行。

## 2. 本轮修复

- 保留 context 锁及 running 拒绝检查，额外验证失效范围非零且不溢出。
- 持有 FEX `GetCodeInvalidationMutex()` 独占锁，先 `InvalidateCodeBuffersCodeRange`，再对存活线程逐一 `InvalidateThreadCachedCodeRange`。零线程时也失效共享缓存。
- 增加返回不同常量的 A/B 汇编 fixture，验证同 VA 的翻译身份随发布改变。
- G08a：100 次 A/B 发布，每次创建、执行、销毁线程；G08b：100 次发布，保留两个停止线程，每次分别执行并检查停止寄存器未被失效操作改写；G08c：清理后线程数为零。
- 更正 address-space 头文件仍残留的“掩码索引碰撞必然执行错误 block”注释；该说法混淆了索引与完整地址匹配。

没有改 FEX、VIXL、TSO 设置或其他子仓。完整相关源码差异保存在 [source-fix.patch](followup-2026-09-08/source-fix.patch)。本次没有实现 context 级 quiesce 事务，也没有把顺序运行的两个 guest 线程当作跨 host owner 并发验证。

## 5. 后续优先级

1. **CPU/地址空间发布事务**：绑定 token 的具体 context/address space/epoch，统一 CPU 与 writer 准入。当前 `Write()` 没有 active-quiescence 检查，`Quiesce` 不协调运行线程；仅持 cache mutex 不能覆盖“改字节到重新执行”的整段事务。
2. **runner 与证据**：将 unit evidence 和完整 acceptance 分开；SSE2 paddq 不等于 MXCSR 舍入，裸 HLT 不等于 illegal instruction/signal 全覆盖。新 G08 尚未映射到 runner，也不能直接升格为 M09。修正实际 SHA、capability、scope、退出码/timeout 和缺项状态；不要使用旧 aggregate PASS 数或“backend 未实现”解释当前状态。
3. **HLE/控制与 app**：补调用期 span/长度/lease、真实 guest HLE/callback，以及中断、有限 Step、信号/调试和 JNI/Surface 生命周期。均按 4 KiB 当前范围推进。

本轮关闭了可以在停止线程、显式发布条件下独立验证的实际执行故障。没有 APK、PS4 游戏、VR 或 renderer 成果；这些不是 36/36 可以外推的结论。
