# Beat Saber PSVR 生命周期与驱帧盘点（CUSA12878 1.00）

本记录对应第一阶段 SBS 的第一轮实施，目标是把 PSVR 生命周期和驱帧边界先固定下来。它使用本体 PKG 的解密 eboot 做静态导入/PLT 调用盘点，静态调用次数不是运行时命中证据。

已准备的 `/Users/bytedance/game/ps4/firmware/11.00_sys_modules/` 中包含
`libSceHmd.sprx`、`libSceVrTracker.sprx`、`libSceCamera.sprx`、
`libSceHmdSetupDialog.sprx`、`libSceMove.sprx` 和 `libSceVideoCoreServerInterface.sprx`；
它们可以作为后续同库导入和版本差异核对的只读参考。

## 已确认的调用链

Beat Saber 1.00 的 eboot 有 704 个静态导入符号，扫描到 26,982 个 `call → PLT` 调用站点（没有把 PLT 自身的 `jmp` 计入）。关键链路是：

```text
HmdInitialize315 → HmdOpen → VrTrackerInit/RegisterDevice
    → CameraOpen/Start/GetFrameData
    → VrTrackerGpuSubmit → VrTrackerGpuWaitAndCpuProcess
    → VrTrackerGetTime/GetResult
    → HmdReprojectionInitialize
    → HmdReprojectionSetDisplayBuffers
    → HmdReprojectionStartMultilayer
    → 每帧 GnmSubmitAndFlipCommandBuffers
       └─ PatchFlipRequest → VideoOutSubmitEopFlip
    → HmdReprojectionSetUserEventStart/End
    → Stop → UnsetDisplayBuffers → Finalize
    → VrTrackerUnregisterDevice/Term → HmdClose/Terminate
```

第一阶段需要关注的不是一次性把所有 VR 函数改成成功，而是保留这条顺序和每帧边界：

- `GpuSubmit` 代表 tracker 工作开始；
- `GpuWaitAndCpuProcess` 代表 tracker 结果可以被消费；
- `GetTime/GetResult` 为游戏提供预测时间和当前诊断姿态；
- GNM 的 `SubmitAndFlip` 经过 `PatchFlipRequest` 进入 VideoOut EOP flip；
- host presenter 真正完成 present 后，才能释放这一帧的复用状态；
- Stop/Finalize 必须先终止运行帧，再清理显示缓冲、tracker 设备和 HMD 句柄。

静态盘点没有发现该版本直接导入 `sceVideoOutRegisterStereoBuffers`。因此 SBS 的第一条实现路径先放在 `sceHmdReprojectionSetDisplayBuffers` 与现有 GNM/VideoOut flip 的连接处，不能凭函数名假定一个未被游戏调用的立体注册接口。

## 第一轮代码实施

新增 `Core::HostRuntime::GuestVrSession`，以 session/generation 保护 HLE 和 presenter 之间的生命周期：

- 状态：`HmdInitialized → HmdOpen → TrackerInitialized → ReprojectionInitialized → Running`；
- 帧阶段：`Acquire → TrackerSubmitted → TrackerProcessed → Submitted → host present complete`；
- 每帧有 generation、sequence 和预测时间；旧 session 或停止期间的帧提交会被拒绝；
- `GuestGraphics` 持有 per-session 的 SBS 输出模式状态，并绑定 HMD、VrTracker、VideoOut；
- HMD 初始化/打开/关闭/终止、tracker 初始化和状态机本身已进入这个模型；实际 reprojection 启动入口仍因结构体 ABI 未恢复而拒绝成功；
- 生命周期状态机不再自动启用诊断姿态；没有 Android 摄像头/HMD provider 时，`GetResult` 返回具名的摄像头未连接错误，不伪造 `connected/tracking/quality`；
- EOP flip 被视为 guest submit，VideoOut presenter 真正完成 present 后才结束 active frame。

当前诊断姿态不是真实 HMD/Move/Camera 实现，不能据此宣称 Beat Saber 已经可玩。未完成能力仍需按 HLE 清单保留具名状态。

## 针对性验证

Android ARM64 目标构建通过：

```text
cmake --build build/android-host-api33/native \
  --target guest_vr_session_tests shadps4_host -j 6
```

设备上运行生命周期单测：

```text
GUEST_VR_SESSION checks=17 failures=0
```

该设备验证的是生命周期状态机和跨 generation 拒绝逻辑，不是 Swan OpenXR 或 Beat Saber 运行验收。随后重新连接的 AYN Thor（设备序列号 `9c2841a4`，不是 Swan）已完成本体树和依赖模块准备，实际顺序为 `eboot.bin → libSceFios2.prx → Il2CppUserAssemblies.prx → PS4Util.prx → libc.prx`。本轮生成了 1164 条导入审计：`runtime_bound=618`、`guest_export=347`、`refused=185`、`not_relocated=14`；拒绝项仍集中在 GNM/Posix/libkernel 及 HMD/VrTracker 未恢复入口，Camera 8 和 Move 7 已进入无 provider 的 guest adapter，不能将静态存在或具名拒绝当作真实设备能力。

设备运行边界已经越过最初的文件映射崩溃：Beat Saber 首个 guest 文件 `mmap` 现在通过 session 文件描述符和 host fd 的生命周期桥接完成；随后补齐了 `pthread_setcancelstate`、event flag 创建/等待/取消、libkernel 具名异常入口、鼠标未初始化语义、SaveData memory 的数据描述符桥接、VideoOut capability/mode/configure 的受检输出、equeue user event 族、Android GPU worker 缺少桌面时钟时的 `NativeClock` 回退，以及 HMD/VrTracker/Camera/Move guest 参数校验桥接。最新有界启动进程（PID 15740）持续出现 Oboe 音频回调和定时 `sceGnmSubmitDone`，但屏幕证据显示 Guest flip=0、Draw/dispatch=0；这只证明进程/音频路径存活，不证明游戏出帧，不证明已经到达可操作菜单、SBS 输出或 VR tracking。

设备日志中 `libSceIme`、`libSceMove`、`libSceMouse` 的 `SysmoduleLoad` 返回 `0x805a10ff` 是 Android provider 缺失的具名结果，不应伪装成成功。当前 PSVR 导入族中 HMD 已有 20/21、VrTracker 已有 12/13 个入口进入受检 Android bridge；`sceHmdReprojectionStartMultilayer` 和 `sceVrTrackerGetPlayAreaWarningInfo` 继续拒绝，因为它们仍缺少多层/输出结构体或 provider 语义。`sceHmdReprojectionSetOutputMinColor` 使用 XMM0..XMM2 的真实 SysV 浮点参数类，已按寄存器读取，桌面接口仍只返回已有 stub 语义。Camera 的 8 个入口现在只做 guest 结构校验并返回 no-provider 语义，其中 `sceCameraOpen` 明确不调用桌面固定地址映射；Move 的 7 个入口保留初始化/句柄及 no-controller 结果。下一批继续处理真正的 HMD/tracker 输出和 SBS buffer 所有权，而不是伪造 camera/Move 数据。

完整静态功能族映射见 [beat-saber-psvr-static-call-map.json](psvr-sbs-20260918/beat-saber-psvr-static-call-map.json)；本轮设备导入审计原始文件为 `files/host/log/guest-imports.json`，按实际 binding 统计，不能只看 UI 截断的首条 unsupported。

## 结构体复核后的边界（2026-09-18）

上面的调用链是静态导入关系，不能当作已经确认的运行时参数顺序。固件复核发现 `sceHmdReprojectionInitialize` 实际为 `(param, mode, reserved)`，其中 `param` 是至少 `0x38` 字节的 guest 记录；此前把它归入无参数 HLE 是错误的。`SetDisplayBuffers` 和 `StartMultilayer` 也仍有未恢复的指针/层描述参数，不能用现有空参数原型宣称已接通。精确字段、guest 地址转换和真实设备结果请以 [PSVR HLE ABI 复核](../psvr-hle-abi-structure-audit-20260918.md) 为准；当前代码的状态机单测不等于游戏运行验收。

## 2026-09-18 ABI follow-up

本轮基于固件 `libSceHmd.sprx` SHA-256 `c5005afcb8bddeaa6de23cd581eabe080087bb45b36c8a9dc89cf6af227f0e71` 和 `libSceVrTracker.sprx` SHA-256 `3a8718d1fa72768d173bfc6d6211934b573c1cc94d3543124cc2e0bc8b050163` 复核剩余 PSVR 入口。`sceVrTrackerGetPlayAreaWarningInfo` 固件导出为 `+0xb080`，固定读取并复制 `0x40` 字节；代码已补 `size/offsetof` 护栏和 reserved 全零检查。未初始化返回 `NOT_INIT`，非法记录返回 `ARGUMENT_INVALID`，有效记录在没有 provider 时返回 `NOT_SUPPORTED` 且不写回。`sceHmdReprojectionStartMultilayer` 的 `+0x17a50` / copy helper `+0x17950` 证实 `0xa8` 步长，但第四、第五参数的语义和嵌套 GPU 对象仍未恢复，因此 Android 继续拒绝该入口。机器可读证据见 [psvr-remaining-abi-evidence-20260918.json](psvr-sbs-20260918/psvr-remaining-abi-evidence-20260918.json)。

## Android SBS 虚拟 HMD 与陀螺仪头动（2026-09-18）

为避免 Beat Saber 在没有 PSVR 时直接走 SetupDialog 取消分支，本轮加入了 Android 端的
最小虚拟 HMD provider。`NativePadBridge` 建立 session 时启用 `GuestVrSensor`，从
`Sensor.TYPE_GYROSCOPE` 接收手机陀螺仪样本，通过时间戳积分并归一化四元数；失焦和 session
结束会注销监听并清空姿态。手柄数据没有作为本轮目标。

guest 侧现在有以下边界：

- HmdSetupDialog 的 7 个导入已实际进入 Android bridge；SBS provider 启用时
  `GetResult` 返回成功，desktop/no-provider session 仍返回 `USER_CANCELED`。
- HMD 设备信息、FOV、惯性状态和 VrTracker HMD 结果使用受检的虚拟设备记录；Tracker 结果
  的方向和角速度来自 `GuestVrSensor`，不伪造 camera/Move/手柄数据。
- `sceHmdReprojectionStartMultilayer` 仍保持 refused，`SetDisplayBuffers` 仍只完成 ABI
  校验，左右眼 buffer 的资源所有权、SBS 拼接和 presenter 输出没有提前宣称成功。

本轮设备单测在 AYN Thor 上通过：

```text
GUEST_VR_SENSOR z=0.479060 w=0.877782 error=0.000365
```

最终 APK `app-fdroid-debug.apk` SHA-256 为
`b4c4829c5cb76cf23232025dd1eda429111515dbf30d743f40361e404a70c9bf`，设备复验启动进程为
PID `23765`，导入审计为
`runtime_bound=624`、`guest_export=347`、`refused=179`、`not_relocated=14`；Android logcat
确认 `vrSbs enabled=1`。但该有界窗口仍没有 HMD/VrTracker 实际调用、第二次 guest flip 或
Draw/dispatch，屏幕仍不能作为 SBS 输出证据。运行原始日志和截图保存在
`build/psvr-sbs-20260918/virtual-gyro-20260918/`，因此下一步应继续定位首帧前等待链，再接
`SetDisplayBuffers`/multilayer 和左右眼 presenter，而不是把虚拟姿态单测当成 Beat Saber
可玩验收。



## SBS 首帧可见性（2026-09-19）

本轮已经把目标推进到 Android SBS 画面可见。设备仍为 AYN Thor（序列号 `9c2841a4`，不是
Swan），图形驱动为 Turnip。`GuestVrSensor` 在 Android session 建立时接收
`Sensor.TYPE_GYROSCOPE`，姿态积分结果继续供 HMD/VrTracker 的受检 guest 记录使用；手柄和
OpenXR 仍不在本轮目标内。

Turnip 对 Beat Saber 的 VideoOut 图像存在一个特定边界：CPU readback 可以取得带有 Beat
Games/Unity 启动画面的源帧，但同一图像的采样和 GPU image transfer alias 在该路径上得到零
像素。因此 Android presenter 暂时采用受控的 SBS bring-up fallback：对第一张有实际颜色的
VideoOut 源帧做一次 guest backing snapshot，经 host utility buffer 缩放后复制到 presenter
frame 的左右两半；后续全黑的可复用 VideoOut buffer 不会覆盖已经可见的缓存，并会每隔一段
时间尝试用新的非黑帧推进。

设备截图证据：`build/psvr-sbs-20260918/visible-sbs-20260919/` 下的 `sbs-8s.png`、
`sbs-18s.png` 分别在约 8 秒和 18 秒取得，均显示左右并排的 Beat Games 画面；重新安装
最新 APK 后，`sbs-unity-8s.png`、`sbs-unity-18s.png` 和 `sbs-unity-48s.png` 又显示了左右
并排的 Unity 启动画面。各截图状态层均显示 `FPS 60.0`、`Guest flip 60.0`，证明 presenter
可以随有颜色的源帧推进并稳定提交；这不是 Beat Saber 已经进入可操作菜单或关卡。

最新 APK SHA-256 为 `e65c102d615de03ce11b49a9af891126a7be51e1798c23aca12d6d2905c508e1`，复验进程 PID 为 `26843`；运行日志、Activity 状态、截图和设备单测输出保存在 `build/psvr-sbs-20260918/visible-sbs-20260919/`。设备执行 `guest_vr_sensor_tests` 输出 `GUEST_VR_SENSOR z=0.479060 w=0.877782 error=0.000365`。

当前明确边界：

- SBS 使用同一源帧复制到左右眼，姿态已经进入 HLE HMD/VrTracker 结果，但尚未做基于姿态的
  真正 reprojection 或视图变换；
- `sceHmdReprojectionStartMultilayer` 仍具名拒绝，OpenXR session 尚未建立；
- 画面目标已越过“黑屏/无出帧”，但还没有菜单、节拍关卡、动态逐帧双眼渲染或手柄验收；
- 该 CPU relay 是 Android/Turnip bring-up fallback，后续应在保留证据的前提下恢复 GPU 直采样
  路径，并接入 Swan 的 OpenXR 生命周期。
