## 状态与锁序决定

| 状态 | 持有者/准入 | 允许的转移 |
|---|---|---|
| Idle | 无 active epoch，允许新工作 | context 锁内 BeginDrain |
| Closing/Draining | context 持有 QuiescenceDrain；它不是能发布代码的 token | 向所有 running owner 发 Pause，再等待 ack、execution leases 和 pins |
| FailedClosed | 同一个 drain 和内部 tickets 保留，新 Run/Create/Resume/writer 仍拒绝 | 显式重试 QuiesceContext；不得定时自动重开 |
| Quiescent | FinishDrain 将隐藏的 reservation 移交为唯一 QuiescenceToken，记录 owner 数 | token 内变更/清缓存；token 释放结束对应 epoch |

- context coordinator 用独立 try-lock 拒绝并发调用；状态检查/owner 注册采用 **context → space**。等待 ack、lease 或 pin 时不持 context 锁。
- space 调 sink 时释放 space 锁并保持 in-flight 计数。sink 持 **context → FEX invalidation** 锁；FEX 的 guest range 查询只读 space，不反向调用 context。
- Run 的 lease 覆盖整次调用；若它恰好在 BeginDrain 前取得 lease、尚未标记 running，则在 context 锁内看到 gate 后退出，lease 纳入 drain。
- QuiescenceDrain 内部封装 token，但不向调用者暴露授权；FinishDrain 前不能用它发布/改映射。没有新增裸 context 回调，沿用 token 的 address-space liveness 和匹配 epoch 释放规则。
- 超时恢复是“排空后重试成功、显式释放 token”；没有 Abort API。上下文销毁仍要求调用者先终止/回收 owner，不保证与活跃 Run 并发析构安全。
- 内部 Pause 被移除后，外部请求的最新 epoch 重新成为可 Resume 的 epoch；snapshot/stop epoch 不重新捕获。G24 仅验证两种 Cancel 时序，不能替代 100 轮完整请求/故障矩阵。
