# A0 首个验证 APK — 编译接线通过、真机启动/身份通过、guest 运行暴露 FEX 分配器平台缺陷

日期：2026-09-11。分支 `codex/android-fex-round2`。设备：AYN Thor（kalama / SD8Gen2），Android 13 / API 33 /
ARM64 / host page 4096，`ro.build.fingerprint = qti/kalama/kalama:13/TKQ1.231222.001/eng.Thor.20260206.163241`。

本记录对应 [N4-to-APK 执行 spec](../../specs/android-fex-round2-n4-to-apk.md) 的 **A0-a（工程/依赖/工具链锁）**
与 **A0-b（最小进程内闭环）** 的首次真机执行。结论：**APK 可重建、可安装、可启动；native 身份读取正确；
但 in-process guest 执行在 `CreateFexContext` 内部因 FEX 64-bit 对象分配器在 ART 进程 VA 布局下无法预留 64 MiB 区域而
`ERROR_AND_DIE`（SIGILL）。** 这是 A0 明确要暴露的平台问题，运行验收计为 **FAIL / 待修**，不据此关闭任何门槛。

## 1. 工程与工具链锁（A0-a）

（`add_subdirectory cmake/fex`），未复制 FEX 链接列表、未把 CLI ELF 当外部服务、未引入参考工程的 glibc 安装器。

**A0-a 期间修复的编译接线缺陷（本次改动）：**

1. `build.gradle.kts` 缺少 Kotlin Android 插件 → `.kt` 源不编译进 dex，安装后 `ClassNotFoundException: MainActivity`
   启动即崩。已在根/`app` 两处加 `org.jetbrains.kotlin.android` 2.0.20 并设 `kotlinOptions.jvmTarget="17"`。
2. `app/build.gradle.kts` 用内联 `java.util.Properties()` —— Gradle Kotlin DSL 里裸 `java` 解析成 Java 插件扩展
   访问器而非 `java` 包，编译失败。改为顶部 `import java.util.Properties` 后不带限定使用。
3. `local.properties` 的 `ndk.dir` 与 `android.ndkVersion` 默认值冲突（CXX1104）。移除 `ndk.dir`，由 `ndkVersion` 决定。
4. CMake 版本 pin 3.30.5 不存在于 SDK（CXX1300）。改为 SDK 自带 3.22.1。
5. `validation_jni.cpp:232` 用 `std::string + ToString(StopReason)`，而 `ToString` 返回 `std::string_view`，
   NDK29 libc++ 无该 operator。用 `std::string{...}` 包裹视图。

依赖获取：除 `com.squareup:javapoet:1.10.0`（AGP 8.13.2 依赖）外全部命中本地 Gradle 缓存；该 jar 经隔离代理从
Maven Central 拉取（jar sha1 `712c178d35185d8261295913c9f2a7d6867a6007`，规范值），其余离线。

## 3. 真机执行结果（A0-b）

安装 `adb install -r`→`Success`；启动 `am start -n com.shadps4.fexvalidation/.MainActivity`。

- **通过**：Activity 正常 `performLaunchActivity`→`performResumeActivity`→`Displayed …MainActivity`。无
  ClassNotFound、无 dlopen/链接错误。
- **通过（native 身份，app 自报）**：`page_size=4096 pid=<pid> uid=10156`、`lib_build_id=4455cf48…`、
  `native page_size(syscall)=4096`、`device API=33 model=AYN Thor targetSdk=35`。
- **FAIL（guest 执行）**：worker 线程调用 `runGuestIncrement` → `CreateFexContext` 内 SIGILL。10 次自动
  fixture 与手动 Run 均未产出结果（进程在首次 `CreateContext` 即崩），A0-b 的 10 次基础记录计为 **NOT PRODUCED**。

崩溃链（`device-crash-logcat.txt`，signal 4 / ILL_ILLOPC）：

```
E FexCore : [A] Couldn't allocate object allocator!
F libc    : Fatal signal 4 (SIGILL), code 1 (ILL_ILLOPC) ... tid (fex-validation-)
#00 FEXCore::Assert::ForcedAssert()
#03 FEXCore::Allocator::SetupHooks(unsigned long)+36
#06 Core::GuestCpu::Fex::CreateFexContext(...)+580
#07 Java_com_shadps4_fexvalidation_NativeBridge_runGuestIncrement+1216
```

## 4. 根因（已定位，非随机 SIGILL）

`SetupHooks` → `Create64BitAllocator` → `OSAllocator_64Bit::AllocateMemoryRegions` 在 `[LOWER_BOUND=4GiB,
UPPER_BOUND=1<<VABits]` 区间用 `CollectMemoryGaps(/proc/self/maps)` + `StealMemoryRegion` 收集空洞，需找到 **≥64 MiB**
的一段承载侵入式对象分配器；找不到则 `ERROR_AND_DIE_FMT("Couldn't allocate object allocator!")`
（`references/FEX/FEXCore/Source/Utils/Allocator/64BitAllocator.cpp:526`）。

**对照证据（同 FEXCore / 同设备 / 同 4096 页）：**

- CLI 裸进程 `guest_execution_tests`（push 到 `/data/local/tmp`，`GUEST_CPU_DEBUG=1`）：分配器初始化成功，
  guest reservation base `0x7f8000000`、return gate `0xfc0000000`，G01–G02… 全 PASS。
- 同一 backend 在 **ART app 进程**：`Couldn't allocate object allocator!` → SIGILL。

差异是**进程 VA 布局**：ART/zygote + 大量映射库把 4GiB 以上区间碎片化，使 FEX 的 64-bit 分配器预留不到连续 64 MiB
（或 `MAP_FIXED_NOREPLACE` 在 ART 布局下的可用空洞不足）。这是 FEX-on-Android 的嵌入平台缺陷，属**主仓适配器**职责
（FEX 树禁止 AI 改动）。FEX 已暴露嵌入路径 `Setup48BitAllocatorIfExists` 与 `Create64BitAllocatorWithRegions(Regions)`
（显式区域），是后续修复的候选入口，但方案设计属 E 级工作，未在本次实现。

## 5. 本次为可见性所做的永久性改动

- `src/core/guest_cpu/fex/fex_context.cpp`：`GUEST_CPU_DEBUG` 打开时，LogMan Msg/Throw handler 在 `__ANDROID__`
  下同时输出到 logcat（tag `FexCore`）。此前 stderr 在 Android 被丢弃，backend assert 只表现为裸 SIGILL 无消息。
  正常路径无副作用；`guest_cpu_fex` 已 PUBLIC 链接 `log`。
- `android/fex-validation/.../validation_jni.cpp`：`runGuestIncrement` 首次调用前 `setenv("GUEST_CPU_DEBUG","1",0)`，
  使 assert 文本可在真机捕获。
- `MainActivity.kt`：结果同时镜像到 logcat（tag `FexValidation`）并在启动时自动跑 10 次 fixture，便于多屏设备上
  无需 uiautomator 即可采集设备证据。

## 6. 待办（本次 NOT_RUN / 未收口）

  无 HLE loop 的 Start/Pause/Resume/Stop（热身后每次 ≤1s）与已发布 snapshot 摘要。当前均 NOT_RUN。
- **A0-a 链接审计**：DT_NEEDED、符号版本、导出可见性、allocator 分配/释放归属的逐项核验未做。
