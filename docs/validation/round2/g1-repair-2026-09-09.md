## 为什么原来的 70/70 不足以关闭 G1

复核先重新编译旧实现并跑了 API 探针，未依赖对方总结推断：

| 原问题 | 实际观察 | 修正 |
|---|---|---|
| paused Cancel 没有唤醒 SleepThread | Cancel 的 WaitStopped 超时；owner 没有退出 | Pause 正常返回 Run，已停止 Cancel 使用冻结回执 |
| 运行态 Cancel 不发布 ack | Run 已返回 Cancelled，WaitStopped 仍 Timeout | Pause/Cancel 共用 owner 发布流程 |
| WaitStopped 每读一次增加 stop_epoch；恢复后旧 ticket 还能成功 | stop_epoch 从 2 变 3；运行态得到“新安全点” | 缓存 owner 快照，重复读不变，消费后的 ticket 拒绝 |
| Resume 使用宽松的 `acked >= epoch` | 新 Pause 已 ack 后，旧 Resume 仍成功 | 只接受当前最新 request/acked epoch |
| SleepThread 停驻但 entry.running 仍为 true | 停止态 ReadRegisters 返回 AlreadyRunning，owner 无法处理 setter | Run 返回 owner 的命令队列，支持停止态 owner 写入 |
| G14 没有观察 B 的 guest store，忽略失败的读与销毁 | 软件标记不能证明并行进度，错误 owner 销毁失败 | gettid + 两份实际 guest counter；暂停 A 期间观察 B 前进；owner 自行销毁 |
| MXCSR 只更新 CPUState，执行仍用 host FPCR | 把转换输入改为 -1.75 后，guest toward-zero 错得到 -2 | Run 进入时按 MXCSR 建立 ARM64 FPCR；退出恢复 host fenv |
| 每次 context 初始化都 SetupHooks | 新增真实 context 重建测试触发 FEX allocator 断言 | FEX 进程级 allocator 只安装一次 |

原始材料：[旧 suite](g1-2026-09-09/baseline.txt)、[epoch 探针](g1-2026-09-09/api_epoch.txt)、[paused Cancel 探针](g1-2026-09-09/api_cancel_parked.txt)。探针源码包含测试 harness，复现旧结果必须在旧基点 checkout 使用它。原零间隔探针的一次运行通过，**没有复现原作者提到的零间隔 SIGILL**，所以这里不把它当成已确定根因。

## 当前停止和恢复规则

详细 pinned 源码依据见 [G1 技术决定](g1-control-decision.md)。本仓开启 FEXCore 的入口 interrupt-page 检查并关闭 MULTIBLOCK，controller 保护独占页面，在 JIT 入口通过 stop-spill stub 正常返回。删除了异步 host stack 备份、SIGILL 恢复和 SleepThread 停驻路径。

- WaitStopped 只返回冻结记录；新的 request 可以复用已经停止的快照，但不会凭空产生新的 stop_epoch。
- Resume 仅消费最新回执对应的请求，owner 再调用 Run；不自动启动执行。WriteRegisters 在 owner、停止态和匹配 stop_epoch 下执行，写入后推进 stop_epoch。
- 不可恢复的 GuestFault/BackendFailure 保持优先级，不能通过 Cancel、Resume、直接 Run 或 setter 升级成正常 SafePoint。
- 只把 JIT block 的第一个 interrupt store 视作入口。即使关闭 MULTIBLOCK，REP 等 IR 内部后向边也可能有检查；这些内部检查仅跳过 probe，不能把部分完成的指令伪装成可写边界。任意长指令/HLE 的停止预算不是本次已证明的范围。
- 每次 Run 安装/恢复 owner 的 altstack，并保存/恢复 host FP 环境。当前使用基础 SIGSEGV 链接，ART 的完整 handler/flags/mask 共存仍需 G4 实测。
- FEX allocator 的 VA 保留属于进程生命周期；重复 context 不重复分配全局 arena。不宣称动态卸载或 RSS 清零，G4 仍须做热身后的资源基线测试。
- 回执发布时已离开 ExecuteThread；Run 函数尾部仍会释放 execution lease。G2 必须等待 lease 真正排空，不能把单个回执当成 mapping transaction token。

## 本轮验证

当前最终源代码的 [canonical 运行](g1-2026-09-09/g1-complete.txt)、[runner 内运行](g1-2026-09-09/v0-results-complete-suites/guest_execution_tests.txt) 与 [空 embedder 构建目录运行](g1-2026-09-09/g1-clean-complete.txt) 均为 **81/81**。空目录重新生成 fixture 并重编本仓 adapter；它复用了固定 FEX 静态库，**不是 FEX 全量 clean rebuild**。

| G1 项 | 本轮有效证据 |
|---|---|
| R2-C01 | G14：不同真实 gettid，A/B 均执行 store；A 停止且 counter 冻结期间 B 继续 store；恢复 A 后两者均前进 |
| R2-C02 | G11/G13：100 次每轮先观察实际 guest 进度再 Pause，无 20 ms settle；记录每轮 request/stop epoch、guest counter、微秒耗时及 p50/p95/max；最终 Cancel ack |
| R2-C03 | G15/G17：100 组并发 Pause/Cancel；100 组并发 Resume/Pause；100 次强制 Timeout 后迟到 ack；100 次真实 context 重建拒绝旧 handle/ticket；100 次真实 HLT fault 优先于随后 Cancel |
| R2-C04 | G16：10 次暂停后写 GPR/RIP/XMM/MXCSR/FS/GS，以 guest 内存输出核对；负数 SSE 转换覆盖四种 rounding，且与刻意设为相反方向的 host 模式区分；running/wrong-owner/stale 写拒绝；host rounding 和已有异常标志保留；G12d 非零 deadline 在执行前拒绝 |

其他回归：host contract 34 项、Android contract 34 项、host ABI 14 项、bionic smoke 12 项、runner accounting 12/12；[新证据负例](g1-2026-09-09/g1-evidence-regressions.txt) 验证 G1 ownership/app 降级与未解析汇编重定位拒绝。V0 runner 为 **10 PASS / 0 FAIL / 47 NOT_RUN，另 3 项延期**。[R2 24 项记录](g1-2026-09-09/round2-results.json) 仅将 C01–C04 的 auxiliary 标为 PASS，最终 app 项保持 NOT_RUN。

本次修复中的失败也已保留：`g1-run-01` exit 139 是新增 fixture 对 global label 的未解析跳转，导致错误执行后续字节；改为 local label，并在生成器拒绝所有未解析 x86 relocations。`g1-run-03` exit 132 是上述重复 allocator 初始化断言。`g1-fp-sentinel` exit 1 是强化负数输入后暴露的 MXCSR/FPCR 不同步；前期正数用例使 host 向下舍入与 guest 向零舍入都得到 1，属于测试盲区。现在覆盖四种舍入，并修复执行态 FPCR。其余中间结果用于保留过程，最终结论只用 manifest 对应的三个最终运行。CMake 现在明确依赖汇编源与生成器，缺 header 不再静默跳过 suite。
