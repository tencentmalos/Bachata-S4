## HN-U01: app-UI start/stop path (PASS)

Driven entirely through the app's own UI (Library → tap "FEX Smoke" card → tap
the **Launch** button in the detail sheet), i.e. UI → `SessionViewModel.launch` →
non-exported `FexSessionService` → JNI `nativeStart` → `SessionCore` →
`FexSessionBackend`. Not an `adb start` of an exported service.

First launch logged the new generation contract on-device:

```
FexSessionService: native: page_size=4096 pid=21495 uid=10157 gen=2
```

Then a 10-round start/stop loop through the UI:

```
round 1:  (gen not captured — timing)  pid=21495 alive
round 2: gen=3   pid=21495 alive
round 3: gen=4   pid=21495 alive
...
round 10: gen=11 pid=21495 alive
```

- **9/10 rounds captured a strictly-increasing generation (gen 3→11)**; every
  round the app process (pid 21495) stayed alive — no GuestFault, no SIGILL, no
  tombstone, no restart. Round 1 missed only the log capture window, not the
  launch.
- Generation strictly monotonic across 10 same-process session rebuilds proves
  the HN0.1 generation/terminal contract on device, and **directly exercises the
  HN0.2 retriable allocator guard**: the old `call_once` swallow bug would have
  made every rebuild after the first fail with OutOfMemory; instead all 10
  FEXCore allocator claims succeeded in one process.
- Natural end path verified once explicitly: after a launch, BACK returned to
  Library (BackHandler not engaged because the session had already reached a
  terminal), i.e. start → execute → self-terminate → UI usable again.
