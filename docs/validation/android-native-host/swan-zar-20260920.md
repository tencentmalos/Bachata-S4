## Implementation

- Library verifies bounded SFO/icon reads through native ZAR inspection, validates base/update TITLE_ID, registers the effective update metadata, and launches the archive path.
- Guest runtime mounts layered base/update/DLC namespaces; ELF, SPRX, module hashes and guest file operations use archive readers.
- Archive descriptor leases provide positioned reads independent of shared file cursors; existing native-file paths remain supported. Archive read errors are not converted to EOF.
- Read-only archive mmap copies outside VM metadata/retirement locks, zero-fills the EOF tail and maintains final protections. A lease keeps the reader alive after descriptor close/unmount.
- Trophy temporary files use the app-owned temp directory.

## Swan startup issues found during actual launch

The first APK (`907e3e42`) failed before reading the game: Android 16 ART owns `0x02000000–0x12000000`, overlapping the old fixed low guest reservation. Activity recreation also alternated library portrait and session landscape, causing repeated failed starts. Fixed orientation restoration to skip configuration-change teardown and avoid reapplying library orientation on recreated activities.

Production reservation planning now subtracts observed host mappings from candidate segments, keeping the original guest envelope. Actual acquisition still uses advisory mmap with exact-address checking, never MAP_FIXED over unowned memory; a racing host mapping fails closed. The existing MemoryManager already consumes actual owned ranges. The first planner revision rejected a zero-length linker mapping emitted by this Swan kernel; it is now treated as occupying no address. Malformed/reversed/overlapping snapshots still fail closed.

Focused planner/mmap tests: 65 checks / 0 failures on Swan including the final zero-length fixture extension (`guest-memory-manager-va2.log`). No FEX child edits.
