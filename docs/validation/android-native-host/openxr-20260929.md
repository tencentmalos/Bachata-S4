# Android OpenXR 首版候选（2026-09-29）

后续模式选择和双目修正见 [2D/XR 与 Swan 复核](openxr-mode-stereo-20260929.md)。本文记录首版时点。

本轮按用户澄清实现 **OpenXR 左右 6DoF 手柄 + 普通蓝牙 PS/Xbox 手柄**。代码基于
`feature/malos/swan_performance` 的 `b0778a7f`，保留之前的 JNI、Summary 与 GPU 调查改动。
这是离线构建候选，**尚不能称为完整 PSVR 支持或 Swan 实机通过**；当前 adb 没有设备。

## 已实现的路径

- 同一 APK 增加 `shadPS4 VR` / `OpenXrActivity` 入口。普通入口不创建 OpenXR runtime。
  原有游戏库、游戏启动和蓝牙输入通道继续使用。已有游戏须先停止，再从 VR 入口启动；不热切换 Vulkan 设备。
- 复用 Foundation 的 Pico loader、OpenXR headers 与 `XrInputSystem`，JNI 环境仍统一走原有
  `JniHelper`。OpenXR 必需的 Activity 仅持有独立 global reference，不创建另一套 VM/线程附着机制。
- `XR_KHR_vulkan_enable2` 创建共享 Vulkan instance/device，由 runtime 选择 physical device。
  传入 shadPS4 当前 driver 的 `vkGetInstanceProcAddr`，不把系统驱动对象和 Turnip 对象混用。
  不支持 Vulkan 1.3/enable2、缺少扩展等情况报具名错误；实际自定义驱动兼容性待 Swan 验证。
- 独立 OpenXR 帧循环负责 events、wait/begin/end、locate views、controller sync。
  `shouldRender=false` 时仍处理输入；失焦、停机、运行时丢失与过期数据会释放 XR 手柄状态。
- Presenter 将已完成的游戏帧复制到独立 GPU image。XR 按自己的刷新节奏重复显示最新完整图像；
  不保留 guest 指针或借用 frame pool 图像，不做 CPU 图像读回。
  timeline 信号先入队，复制 GPU fence 完成后才发布；XR 图像复制完成后才 release。
  XR 的 begin/end/acquire/release 与游戏提交共用 queue mutex，wait 不持此锁。
- 普通游戏使用 LOCAL 空间中距原点 2.5 m、宽 3.2 m、保持源图比例的影院 quad。
  PSVR 图像按显式双眼标记拆成左右 eye-visibility quad，保持独立视图。
- `sceVrTrackerGetResult` 获取 runtime 的头部/双眼与左右 grip 位姿、有效性和角速度；
  Move 手别由 `sceMoveOpen` 的 index/handle 确定，不依赖 tracker 注册顺序。
  Hmd 眼间偏移转换为 head-local，分辨率来自 runtime 推荐渲染尺寸（不是物理面板测量）。
- Foundation 输入补齐独立 grip space、模拟 trigger/squeeze、haptic binding 与 stop feedback。
  PS Move 读取各自手柄的面键、模拟扳机、角速度，并将震动发给对应手。没有假造加速度或位置跟踪质量。
- XR pad 是独立输入源：与蓝牙/触屏按键合并，轴绝对值较大者生效，同幅值蓝牙优先。
  XR 松键不清掉蓝牙仍按住的键；震动同时路由各自硬件，不消费蓝牙的反馈队列。

## 控制映射

| OpenXR 输入 | PS4 pad |
|---|---|
| 右 A / B | Cross / Circle |
| 左 X / Y | Square / Triangle |
| 左/右摇杆，按下 | 左/右摇杆，L3 / R3 |
| 左/右扳机 | L2 / R2（模拟量） |
| 握持 + 同手扳机 | L1 / R1 |
| 握持 + 摇杆方向 | D-pad；两手同时使用时右手优先 |
| 左握持 + 左摇杆按下 | Touchpad click |
| 右握持 + 右摇杆按下，左 Menu | Options |

蓝牙 PS/Xbox 仍使用已有 Android 映射及用户设置，不再次套用 XR 面键转换。
原有 Move ABI 只确认四个面键位；未猜测 Move/Start/Select 的位定义。

## 明确未完成的部分

1. **精确 PSVR 全景投影 / 重投影尚未完成。** 当前重投影共享的 0x38 字节记录没有足够证据证明是
   某个 pose 布局；参见已有 [ABI 审计](../../psvr-hle-abi-structure-audit-20260918.md)。不能猜 offset。
   本轮把最近一次实际 HLE 返回的双眼快照随图像传递，供实验，但它不证明就是该帧使用的绘制姿态。
   默认仍为立体影院。`debug.shadps4.xr_projection_snapshot=1` **仅在下一次启动**打开近似全景投影，
   并写明确 warning；未设或为 0 时关闭。它不是已验证修复，也不提供精确时间扭曲保证。
2. `sceHmdGetInertialSensorData` 的原始输出 ABI 尚未恢复；OpenXR 下返回 unsupported，
   不再成功返回未写入的数据。高层 tracker 读取实际位姿。原有深度/额外 reprojection layer 的限制仍在。
3. 本轮没有实现 VR 中的应用设置面板或 OpenXR 指针点击 Android 游戏库；游戏库使用已有 Android UI。
   可以先在普通入口选好游戏，再用 VR Activity 的 `open_last_game` intent 进入最后游戏。
4. 首版采用有界容量的 GPU mailbox，但每次游戏图像发布会等待一次 GPU copy，XR 每帧另有一次 copy。
   **未宣称性能改善**；需要真机确认显示、色彩、手柄、退出与 GPU 开销，再决定异步环及优化。
5. 头显佩戴优先用 `XR_EXT_user_presence`；runtime 不提供时只能用 focused 状态近似。
   尚未验收真实佩戴事件、运行时 recenter、休眠唤醒、长期切游戏、蓝牙与 XR 同时实握、Turnip/系统驱动对比。
6. 没有改变 PSVR guest 相机/原始惯性/光球硬件能力为“全部支持”；没有把旧 Beat Saber 黑屏等 guest 问题视为已修。

## 验证与交付

候选 APK：[`shadps4-b0778a7f-openxr-candidate.apk`](../../../build/validation/openxr-20260929/shadps4-b0778a7f-openxr-candidate.apk)。
APK SHA-256 `e8dbbb5baa6f77b0d11036a25bccb93a38a75ba75bbdd39d506f1099339660ca`。

| 检查 | 结果 |
|---|---|
| GuestVrSensor（UBSan，macOS） | 54 / 0 |
| Foundation XR mock + PS pad mapping（UBSan，macOS） | 34 / 0 |
| 生产 OrbisPadAdapter + Foundation input（UBSan，macOS） | 62 / 0 |
| Android host + sensor/input test targets | 编译通过，设备测试未运行 |
| APK + runtime androidTest Kotlin | 编译通过，设备仪器测试未运行 |
| APK 包内 host / Foundation loader | SHA 与构建文件匹配 |
| mainline driver | SHA 与正式 86ca 发布匹配 |

Pad 测试仅替换 UI capture 查询与诊断日志；输入合并和物理/XR 反馈路由均跑生产实现。
这 150 项检查不覆盖真实 OpenXR runtime 或 Vulkan queue/swapchain 执行。

构建命令：`cmake --build build/android-host-api33/native --target shadps4_host guest_vr_sensor_tests openxr_input_tests -j6`；
JDK 17 下在 `android/shadps4-app` 运行 `./gradlew :app:assemblePlaystoreDebug :core:runtime:compileDebugAndroidTestKotlin`。
Host 测试用 UBSan；pad 的浮点 `from_chars` 需要本机 Homebrew LLVM/libc++，其可用性标注在测试时配合
`-D_LIBCPP_DISABLE_AVAILABILITY`（显式链接该 libc++，不是调用旧系统缺失的实现）。

最终测试、包和 native SHA 见 [manifest](evidence/openxr-20260929/manifest.json)，
输出见同目录 `tests.txt`。Host、APK 与 Android 仪器测试 Kotlin 编译通过不等于在设备运行过测试。

没有安装到设备，没有提交或推送。打包驱动仍是正式发布的 mainline 86ca；
前轮 Swan GPU 调查的 CleanupPending 不变。
