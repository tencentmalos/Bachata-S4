# Odin3 血源前景黑面：record 定位（2026-10-10）

已确认前景的大块黑面由受损顶点形成的错误三角形覆盖地面造成。异常在几何阶段已经写入深度、法线和底色缓冲；不是后续阴影计算才把正常地面变黑。尚未定位更早写坏这段数据的操作，未修改运行时代码。

## 环境与记录

- 仓库切换到 `feature/malos/swan_performance`，快进到远端 `6730e0075b6d93a0494a01d3e5bf80e13d297cf7`。Mesa 引用同步到 `2b8ed3fc20552e5fe0ed3eca8fe9e2772e494a42`。保留原有两个脏参考子仓及未跟踪的 Madeira 目录。
- 设备 AYN Odin3 / Adreno 830，序列号 `6edb0593`；血源 `CUSA03023`，内部比例 75%，原始输出 1440×810。
- 设备 APK 自报 `v.0.18.0-594-g6730e0075-dirty`，不是本次重新编译安装。原驱动 `Mesa 26.3.0-devel (git-fa9873b2ca)`，SHA-256 `096e8d3501b3a38300a36d7e51ad0fccd57414fd219283d7a1a8ed8b2ce7d9fa`。
- 用 `gpu_replay_capture 3 odin3_black_shadow_20261010` 抓取内置 GPU record，非 RenderDoc RDC。原文件 1,910,402,726 字节，格式检查通过；198 个提交，612 次等待采样，3 帧。回放完成、等待强制放行 0、事件分歧 0。
- 原 record、设备截图、逐事件/逐 draw 缓冲、日志、脚本和存档备份保存在本机忽略目录 [证据目录](../../../build/validation/odin3-black-shadow-20261010/)。设备也保留原 record。

## 定位链

1. 原始呈现图中就有黑面，未经过窗口超分和状态层。
2. 第一帧回放事件 `154`、draw 索引 `10` 首次覆盖正常地面。VS `0x7620368b`，FS `0x8aba0ecd`。法线 MRT 地址 `0x26e090000`；像素 `(100,700)` 从 draw 9 的 `(120,253,152,0)` 变成 draw 10 的 `(80,55,221,0)`。底色、深度也一起变化。
3. 从同一 record 的第二帧取得命令 trace；对应 action `443` / submission `510`，203,256 个 uint32 索引，索引偏移 17,768，三角形列表。最初另抓的 live PM4 属于更晚的游戏帧，仅作辅助，不能与第一帧事件号混用。
4. 顶点描述符：基址 `0x294d68d10`，步长 36，187,032 条记录。实际用到 115,917 个不同顶点，索引范围 0–115,916。Fetch shader 将顶点偏移 15 的字节作为矩阵索引。
5. 参数中的矩阵基索引为 0，变换缓冲 `0x2d29801c0` 长 96 字节，每个变换占 48 字节。但顶点约 84,168–84,216 所在区域的内容突变；其中 17 个被引用顶点的索引字节为 34、36、56、60、63、66、157、192、193，明显超出缓冲范围，位置与其他属性也不再遵循相邻顶点的结构。
6. `0x29504c000` 页的异常字节已存在于 record 初始快照，后续三帧没有该页的 MemoryPages 增量。快照包含抓取前 GPU 独有数据的回写，因此此证据不能单独判定是 guest CPU 写坏，还是 GPU 数据/回写路径出错。
7. 只对 record 副本修改索引：将引用顶点 84,167–84,216 的 **29 个三角形**退化为 `(0,0,0)`，其余 67,723 个三角形及原顶点数据保留。只改初始快照索引页 `0x294d01000` 的 87 个 uint32。三帧成功回放，前景大黑面消失，墙体与地面保留。这是因果诊断，不是修复方案；原 record 和游戏文件未修改。

## 对照结果与边界

| 对照 | 结果 |
| --- | --- |
| 关闭实时 Vulkan recorder | 黑面仍在，随后恢复 on |
| 同一 record，内部比例改为 100% | 黑面仍在 |
| 冷进程切换 Qualcomm 系统驱动回放 | 黑面仍在，日志确认实际使用系统驱动 |
| 回放跳过整个 VS `0x7620368b` | 黑面消失，但正常墙体也消失，只作定位 |
| 仅剔除上述 29 个三角形 | 黑面消失，正常墙体保留 |

系统驱动对照只能说明同一份已异常的数据在两种回放驱动下都会产生黑面，不能排除录制前驱动曾参与数据损坏。现有 record 起点太晚，不能确定最早写坏者；后续应从正常场景开始追踪该顶点页的 CPU/GPU 写入、映射重用及缓存回写。围栏/植被上的其他细碎黑点未被这次实验消除，不能一并归因。
